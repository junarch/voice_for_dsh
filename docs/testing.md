# 如何测试语音插件（testing）

> 回答："除了手动点、用耳朵听，我怎么知道内部管线正不正常？"
> 真实教训：AI 写的转写代码曾每条消息悄悄转写 4 次，用了很久直到 token 账单爆了才发现。
> 手动使用发现不了这类问题，因为**表面（有声音、内容对）掩盖了内部事实（调了几次、花了多少、走了哪条分支）**。

## 0. 核心心法

1. **不问"听起来对吗"，问"每一步发生了什么、发生了几次"。** 把"听感"换成可数指标：LLM 调用次数、TTS 请求次数、缓存命中率、错误码。
2. **每个外部接口都不可信。** 文档会过期、接口会变。对"接口应该怎么表现"的每个假设，要么小实验证实，要么在代码里防御。
3. **发现的事实要固化成可重复的检查。** 实验结论写进文档会过期，写成断言（测试）不会。
4. **断言分两类，别混着信。** "不变量"是我们代码自身的要求，放心长期信；"外部事实快照"是对别人接口某天行为的记录，
   **可能错、会过期**——推翻它必须先拿新证据（跑探针、亲耳听），再同步更新断言+实现+文档三处。测试文件里用醒目注释分开。

## 1. 管线地图（知道要测什么）

```
[DeepSeek 输出完成] -> Host 监听 turn/end(completed|max-tokens) -> 提取最后一条含 text 的助手消息
   -> LLM 口语化转写（独立调用，prompt 由风格预设/语种拼） -> 转写稿缓存（provider/model/prompt/effort 四者一致才命中）
   -> TTS：browser=客户端 speechSynthesis | volcengine=豆包（云端合成） | local=本地 Kokoro（进程内 sherpa-onnx）
        └ local：懒加载模型（冷启动约 3s，之后常驻复用）
                  → splitForStream 分句 → 逐段合成 → Float32 转 Int16 裸 PCM → 按 ~0.5s 音频切段入队
                  → 客户端边取边播（模型已加载时首声约 0.6s）
        | Host 合成 + 一次性音频路由 -> 浏览器播放
```

每一步都有独立失败方式：事件没触发、消息提取错、转写失败/超时/撞顶、缓存没命中（重复烧钱）、TTS 报错、播放失败。
**测试就是逐段验证，而不是只测最后一环。**

## 2. 四层测试手段（从便宜到贵）

### 第 1 层：本地 mock——集成测试 `scripts/test-host.mjs`
不启动 dsh、不花一分钱，用 mock 的 llm/sessions/settings/fetch 加载真实 `lib/index.js` 驱动完整链路；
插件配置按**真实导出的 `Config` schema**解析（含默认值 + volatile 引用），所以"插件能不能被目标版 DSH
（当前基线 `0.2.1-rc.5`）正常加载并解析出配置"这件事本身就有断言兜着（加载即 `TypeError` 这类事故就栽在这条上）。
已固化大量断言，每条对应一个坑：TTS 请求不得含 `[#...]` 标签、数值参数映射、**同一消息重复朗读 LLM 调用数不变**、
撞顶 4 倍额度重试、失败降级、自动播报门控、context_texts 指令组装、音色↔语种归一、重播零 LLM、regen 重新生成、
cache_config 初次/重播下发而 regen/换音色重播不下发等。
每次改完 Host 半必跑。

### 第 1.5 层：本地 mock——Client 半合约测试 `scripts/test-client.mjs`
不启动浏览器，用最小替身加载真实 `lib/client.js`，**真的执行**槽位注册回调：
按上游 `SlotRegistry.register` 的规则校验（list 槽位必须有 `id`、`select` 只有 chain 槽位认），
并驱动 turnTail 徽标的 claim 逻辑（本轮没有可朗读消息 / 该消息没读过 → 必须返回 null 不占位）、
会话 Definition 注册与 zh/en i18n 键对齐。每次改完 Client 半必跑。

### 第 1.6 层：本地 mock——提示音渲染与调度 `scripts/test-chime-ui.mjs` / `scripts/test-chime-playback.mjs`
不启浏览器，用极小的 React 替身把真实的设置页组件渲染成树，断言五层的渐进显隐：
总开关关着时三行不出现、关某行时它的音源与上传不渲染、层头是 `button` 且 `aria-expanded` 正确。
播放侧用假 `AudioContext` 记账，断言：多个会话同时跑只起一份工作音、结束与提问两种音都能响且工作音不停、
审批与子代理不触发、同 key 去重、连续结束只响一次、短素材改按间隔播、缺素材回落到默认音。
改设置页或提示音必跑这两个。

### 第 1.7 层：本地 mock——设置页按引擎显隐 `scripts/test-settings-ui.mjs`
同一套 React 替身，按 `tts.provider` 三档各渲染一次真设置页组件，断言"只对某个引擎生效的参数
不摆在别的引擎下"：系统 TTS / 豆包下没有「高级」层（线程数、分句流式、模型目录），本地引擎下三项都在
且层头摘要带当前值；切引擎走组件自己的 `onChange`，同一实例重渲染后显隐跟着变。
同时覆盖两条前置条件说明：豆包缺 API Key 时自动播报会先失败再回退、成本门控 `autoSpeakCloudTts=false`
时给可操作的原因；自定义网关缺 `wsUrl` 时说明会整段合成。
**改设置页显隐条件必跑**——上一轮 L4 错位就是没有这层防线，只能靠人眼发现。

### 第 1.8 层：本地直连——本地合成探针 `scripts/local-tts-probe.mjs`
绕开插件直接打 `sherpa-onnx-node`：同一句话按不同 `sid` / `speed` 合成，打印音频指纹与时长。
用来分清"模型只出一个声"与"插件没把音色传下去"——后者是插件 bug，前者才是模型问题。
`test-host.mjs` 的对应回归分两层：假引擎证明**接线**（`generationConfig.sid` 等于草稿值），
真模型段（`VOICE_LOCAL_MODEL_DIR` 指向已装模型时才跑）证明**音频真的不同**。

### 第 2 层：本地直连——RPC 接口（dsh 运行中）
一键自检（推荐先跑这个，逐条打印证据、退出码 0/1）：
```powershell
# 端口与 token 以启动日志/地址栏给的为准；下面都用 $base，换过端口只改这一行
$base = "http://127.0.0.1:19387"      # 示例端口
node scripts/verify-installed.mjs --url "$base/?token=xxxx"
```
单项手工打（`curl.exe` 在本机 PowerShell 里可能不可用，改用 `Invoke-WebRequest`）：
```powershell
curl.exe -s -X POST "$base/voice/api/ping"
curl.exe -s -X POST "$base/voice/api/getConfig"
curl.exe -s -X POST "$base/voice/api/meta"
curl.exe -s -X POST "$base/voice/api/preview"            # 试听（豆包产生少量实际调用费用）
curl.exe -s -X POST "$base/voice/api/clientDiagDump"    # 读回浏览器播放链路事件
```
看返回关键字段：`cached`（true=缓存命中没花钱）、`degraded`（true=转写失败走兜底）、`ttsError`、`audioUrl`。
播报"没声音"时先看 `clientDiagDump`：`stream-start` 的 `ctx` 是不是 `suspended`、`stream-end` 的 `played`
是不是 0——把"Host 还没算完"与"浏览器根本没排上播放"分开（冷启动 3 秒、首声 0.6 秒，差这么点时间，
光靠耳朵分不出是没出声还是没排上）。

### 第 3 层：几分钱——真实外呼探针 `scripts/tts-*.mjs`
对火山 TTS 做受控实验（读目标 profile `cordis.patch.yml` 里 `voice.tts.volcengine.apiKey`）。
时长对比只能证明"标签被照读/数值参数生效"这类强信号；
**语气、音色、方言这类只有人耳能判断的效果，必须听音频**。怀疑任何外部接口行为时，先跑探针再改代码。

本地引擎是进程内合成（没有服务、没有端口），四段断言都在 `scripts/test-host.mjs` 里：

- **T21 本地运行时**：模型目录解析顺序、自检读数、停止；
- **T22 本地分句流式**：每 ~0.5s 音频入一段、中途失败保留已播段、首段失败降级整段、单段超时；
- **T23 真模型端到端**：设 `VOICE_LOCAL_MODEL_DIR` 指向解包好的 `kokoro-multi-lang-v1_1` 后会真加载模型、
  合成中英各一句并打印首声/RTF 读数；不设则跳过（不把"没装模型"当失败）。
- **T24 模型安装器**：下载 / 续传 / 校验失败 / 取消 / 磁盘不足 / 删除（注入假 fetch 与假解包，
  零网络、零 348MB）。

提示音另有一组断言（同样不产生外部调用）：三种信号只从客户端状态快照对账（`turn/end` 不参与）、
子代理会话要过滤掉、审批 `approval` 不响、素材上传按魔数认格式并拒绝 `..` 与超限、
启动清扫不误删刚上传还没保存的文件、提示音用独立 AudioContext 不被停止播报连坐。

### 第 4 层：手动验收（最贵，只测前三层测不到的）
浏览器里：设置页渲染、五层里除第一层外**默认折叠**（点开/收起、层头摘要跟着当前值变）、
下拉/滑块交互、朗读按钮状态机、自动播报节奏、提示音上传与试听、方言试听。只在这一层测"人能感知"的东西。

## 3. 账单防御

"转写四次"类问题特征：功能表面正常，成本暗中异常。防御手段：

1. **调用计数**：mock 断言"重复朗读不增加 LLM 调用"。
2. **缓存审计**：`$DSH_HOME\voice-transcript-cache.json` 每条含 `at`（时间戳）、`provider/model/prompt`；
   同一条消息出现多条不同 `at`，= 有重复转写（合理原因：改了配置；不合理 = bug）。
3. **降级可见性**：`degraded=true` 时提示"转写失败已直读"——降级是好事，但**静默降级是账单刺客**。
4. **控制台日志**：Host 进程日志里每个关键分支都有 `[voice]` 前缀日志（auto-speak pending / skipped: gated / transcribe failed / cloud tts failed）。
5. **供应商用量页**：每周扫一眼火山/DeepSeek 用量曲线，和平时的形状对比。

## 4. 怎么和 AI 协作做这些

- **让 AI 先写测试再改代码**："先读 docs/testing.md 和 scripts/test-host.mjs，为要改的行为加断言，跑通后再改实现，改完再跑给我看两轮结果"。
- **要 AI 报告"调用次数"而不是"我测过了"**：让它贴出 `node scripts/test-host.mjs` 与 `node scripts/test-client.mjs` 的完整输出。
- **外部接口假设必须给证据**：问一句"这是实测还是推测？"——探针脚本就是为此存在的。
- **每个 bug 修复后问一句**："这个坑怎么变成一条断言？"
- **git 是时光机**：改坏了一键回退。修复前 `git status` 确认干净，修复后 `git diff` 逐行看改动范围。

## 5. 为什么有些断言看着像"故事"（A/B 类断言的由来）

历史上踩过两个典型坑，正好说明"断言必须贴着原始证据"：

- **内嵌 `[#...]` 标签被照读**（2026-08-19）：风格播报把指令标签读出来了。取证→受控实验（同文本 ±标签对比时长）
  实锤"接口不解析标签、照读"。修法不只是"让 LLM 别输出"，而是预设 prompt 不插标签 + Host 兜底剥离一切 `[#...]` +
  语速/音调改走数值参数。每条修法都固化成断言。
- **"字节级相同"的错误结论**（2026-08-20）：第一版探针比较文件**大小**就宣称"指令无效"——CBR 码率 MP3 相同时长必然同大小，
  哈希一查全不同。教训：**断言必须贴着原始证据（哈希/音频/次数），推理链每步都要能被推翻**。这正是 A/B 类断言分工的由来。
